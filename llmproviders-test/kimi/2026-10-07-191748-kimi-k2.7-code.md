## Points of attention (matrix §6.8)

- `kimi-k2.6` **refuses any temperature other than 1** (`invalid temperature: only 1 is allowed for this model`) — the catalog pins it for this model (requiredParams), and the report header carries the value actually used. A Kimi verdict is not reproducible in the same sense as a verdict at temperature 0.
- Two regional endpoints with **separate accounts**: `api.moonshot.ai` (international, default) and `api.moonshot.cn` (mainland China).
- G-11 closed: check that the host resolved in the report header is the expected one.
- The `moonshot-v1-*` series counts input + output within the same bound — its “8 K” is not an 8 K input window.
- 2026-10-07 is not a result: the account is suspended (`exceeded_current_quota_error`, HTTP 429, `suspended due to insufficient balance`; `GET /v1/users/me/balance` answers `available_balance: 0`, `cash_balance` negative). The retry policy treats that 429 as a rate limit and spends its whole budget on every mode — the run was stopped after nine minutes on the first model and nothing was archived: the refusal quotes the organisation and key ids. The catalogue still answers: `kimi-k2.6`, `kimi-k2.7-code`, `kimi-k2.7-code-highspeed` (262 144 context) and `kimi-k3` (1 048 576), all with image, video and reasoning. The 2026-09-21 lines stand.
