## Points de vigilance (matrice §6.1)

- Cible générique du fallback de `LlmProviderFactory` : une campagne verte ici valide indirectement Docker Model Runner, vLLM et LM Studio. Prouvé en réel le 2026-08-30 : campagne 12/12 contre `api.x.ai` (`grok-4.6`, dialecte OpenAI, base-url seule) — rapport sous `custom-endpoints/`.
- G-05 fermé (LLM-01) : le défaut est passé de `gpt-4` (8 K de contexte, extinction 2026-10-23) à `gpt-5.6-sol`.
- Les modèles actuels refusent `max_tokens` (campagne 2026-08-30 : dix modes rouges sur ce seul champ). Le dialecte OpenAI écrit `max_completion_tokens` depuis cette date — accepté aussi par les générations antérieures (vérifié sur `gpt-4o-mini` le même jour).
- `gpt-5.6-sol` refuse toute température autre que 1 (`'temperature' does not support 0 with this model`) — même classe que `kimi-k2.6`, même remède : le catalogue l'épingle pour ce modèle (requiredParams) et l'en-tête du rapport porte la valeur utilisée.
- `gpt-5.6-sol` raisonne par défaut et refuse les function tools sur chat/completions tant que `reasoning_effort` n'est pas explicitement `none` (mesuré 2026-08-30, `none` débloque l'appel). Le catalogue l'épingle pour ce modèle (`requiredParams`) ; M7 continue de sonder le thinking avec son propre effort explicite.
